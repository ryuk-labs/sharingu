# AGENTS.md — sharingu, the map (any agent, any tool)

sharingu is ONE product: ONE Cloudflare worker and ONE D1 database serve the app (eight tabs), a REST API and an MCP
door to many orgs, and what happens in an org stays in the org. People and their AI tools file contributions through
the MCP; sharingu stores them in D1, inside their org; the app shows them live; people decide on them. The plan and the
current state live in `docs/plan/` — read `docs/plan/README.md` first, then `docs/plan/HANDOFF.md`.

## The layout

| Path | What it is |
|---|---|
| `engine/` | The product. `src/` is the worker (pages, API, MCP), `tools/` its scripts and selftests, `migrate-0NN.sql` the schema. Deploys to Cloudflare Workers as ONE worker for every org, `ryuklabs-agent-r` (`engine/wrangler.jsonc`), ryuklabs its org 1. Depth: `engine/CLAUDE.md`. |
| `contracts/` | The door's contract. `door.declared.json` is hand-typed; `door.json` is GENERATED by `engine/tools/make-door-contract.py` and never hand-edited. |
| `docs/plan/` | THE plan: `BETA.md` (the beta gate, green, each line with its proof) · `README.md` (the model + how we work) → `HANDOFF.md` (where we are, the queue) → `SPRINTS.md` (the slices, sprint by sprint) → `ARCHITECTURE.md` → `INVENTORY.md` → `MCP.md` (the door) → `LOOK.md` → `PLATFORM.md` (the platform road, every open item) → `MARKETPLACE.md`. |
| `docs/` · `orgs/` | Install paths · where an org starts. |
| `.claude/` | Claude Code's settings and three skills (`draw`, `mcq`, `discuss`). No hooks, no agents, no workflows. |

## How we build (owner, 2026-09-30)

- **One sprint, one branch.** A sprint is a branch `sprint-N` off `main` in this checkout. No per-change worktrees, no
  per-change PRs, no verifier per change.
- **Vertical slices.** A sprint is a list of slices in `docs/plan/SPRINTS.md`. A slice is built in this order: the
  table → the MCP/REST write → the screen that reads it. A slice is committed when its smoke is green.
- **Smoke per slice.** `sh engine/tools/smoke.sh` boots the local worker, files through the MCP and loads the tabs.
  It is small and fast on purpose. The owner can open the local app after every slice.
- **Tests follow the code.** When a slice replaces a page, the old checks that pinned that page's text are DELETED and
  replaced by smoke cases plus a selftest for any new logic. Never re-pin old text line by line.
- **One review at sprint end.** The gate and the four suites run once (`sh gate.sh`, `sh evals.sh`, `sh sims.sh`,
  `sh tools/tabs-verify.sh`, `sh tools/verify-live.sh` in `engine/`; each suite starts a fresh local org, as the smoke
  does), one independent read-only review reads the whole sprint diff, the fixes land on the branch, then ONE PR is
  merged.
- **Ship after the merge**, with the owner's OK, in the order `sh tools/ship-plan.sh ryuklabs` prints (from `engine/`):
  the budget, the migrations one at a time, the code with the import on the preview, then the walk on live.
- **Builders.** The main session plans, briefs, reviews and commits. Opus sub-agents write a slice's code from a brief.
  Builders run one at a time when they share files (`src/index.js`, `src/mcp.js`); in parallel only on disjoint files.
- **Forks go to the owner as MCQs**, recommended option first.
- **Update `docs/plan/HANDOFF.md` at every stop** and tick `docs/plan/SPRINTS.md`. That is the only status ceremony.

## The commands (from `engine/`)

```
sh tools/smoke.sh                     # per slice: a fresh local worker, MCP write -> read -> the tabs (cases in tools/smoke/)
sh tools/dev-local.sh up              # the local app with REAL data: every project imported through the MCP; prints the URL
node tools/ship/after-import.mjs <url> --creds <file>   # then sharingu's history and screen pictures, through preview -> file
node tools/audit/project-audit.mjs --url <url> --creds <file>   # every project's data, read through the door
node tools/page-budget.mjs            # per slice: D1 rows read per screen and per MCP read (local, real data)
node tools/live-walk.mjs              # gate line 1: an admin and a new member on a throwaway project (--live after a ship)
sh tools/gate-rehearsal.sh <url> --creds <file>   # the seven gate lines against a local org
sh gate.sh                            # sprint end: the gate, green by exit code
sh evals.sh                           # sprint end: the eval suite, on a fresh local org (--live after a ship)
sh sims.sh                            # sprint end: the sims, never beside another suite
sh tools/tabs-verify.sh               # sprint end: each seat signs in and walks every tab of the rail
sh tools/verify-live.sh               # after every ship with --live: our tools reach the org's door as themselves
sh tools/cf-budget.sh                 # before anything live: the Cloudflare budget guard (it reads the account's plan)
node tools/make-listing-docs.mjs --check   # the listing's docs page against the contract (gate); generate: no flag (the contract), or --url <worker> --creds <file>
node tools/make-reviewer-org.mjs --url <worker> --local <persist dir> --config <cfg>   # the stores' reviewer org (sprint 9; M4: --live --config wrangler.jsonc --confirm-live ryuklabs-agent-r; codes printed once)
node tools/listing-walk.mjs --url <worker> --codes <the refresh's codes file>   # listing/test-cases.md's eight cases, each as its account (smoke s51 walks the same code)
sh tools/ship-plan.sh ryuklabs        # read-only: this ship's order — migrations, preflights, checks, rollback (--no-import: no import hook)
sh tools/migrate.sh migrate-0NN.sql   # one migration on live, a Time Travel bookmark first
sh tools/ship.sh ryuklabs             # the ONE deploy command, resumable by its run record (SHIP_PREVIEW_HOOK: a step on the preview)
node tools/operator.mjs allow --email <e> --live --config wrangler.jsonc --confirm-live ryuklabs-agent-r   # the operator: a sign-up code (printed once), refused once the beta's 50 places are taken unless --beyond-cap (sprint 12); also list-orgs · set-plan · raise · suspend (sprint 8) · set-openai-challenge · clear-openai-challenge (sprint 11) · requests · allow --request <id> · decline --request <id> (sprint 21) · requests · allow --request <id> (sprint 21: the open requests in line; approve one, its code printed once)
node tools/org-undo.mjs plan --org <id> --live --config wrangler.jsonc --confirm-live ryuklabs-agent-r     # one org's export / restore / verify / delete
```

A contract change: edit `contracts/door.declared.json` or the registries in `engine/src/index.js`, then
`python3 engine/tools/make-door-contract.py`.

## Laws

- **The MCP is the only input; D1 is the truth; every screen reads D1 live.** No page reads a published file.
- **One product; orgs and projects differ only by data.** No per-org or per-project code (`docs/plan/PLATFORM.md`).
- **Secrets stay machine-local.** Never print a value, never commit one. Credentials:
  `set -a; . ~/.sharingu/env-sharingu.sh; set +a`.
- **The ryuklabs account is on Workers Paid since 2026-10-02** (owner): D1 allows 25 billion rows read and 50 million
  written a month, with no daily limit, and a request gets real CPU time. The per-screen row budget below STAYS, because
  an outside team installs sharingu on its own account, which may be free.
- **Local first, and inside the Cloudflare FREE tier for any org that is not ours.** A free account's daily limits are
  5,000,000 D1 rows read, 100,000 rows written and 100,000 requests, shared by everything on it; a request also gets
  about 10 ms of CPU and 50 subrequests. Develop and test on the local worker. After each slice run `node tools/page-budget.mjs` against the local
  app with real data: a screen or MCP read over 1,500 rows is flagged and must be justified or cut (aggregate in SQL,
  never read a whole table to count it). The local worker does NOT enforce the CPU or subrequest limits, so the first
  live import and the first live load of each heavy page are checked by hand at ship, small batch first.
- **The Mini is shared.** One heavy suite at a time; check `uptime` before a full suite.
- **A claim carries its proof**: the command, its exit code, its output.
- **No dead code, no dead docs** (owner, 2026-10-02): a doc names only what exists (`tools/check-docs.py` is a gate step).
- **Rules live in this repo**, not in a session's memory and not on a board.
